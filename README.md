# 无人系统 PHM 可交互原型

基于公开真实数据展示无人机螺旋桨故障诊断、电池 SOH/RUL、伺服台架振动诊断、独立测试结果与告警复核。现有 `source/` 合成示例保留，**不会作为真实实验的自动替代数据**。

## 启动

推荐 Python 3.11–3.13。首次安装：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

`requirements-lock.txt` 记录本次实际验证环境的精确依赖版本；复现实验时可使用 `pip install -r requirements-lock.txt`。

已有本地实验结果时，直接运行：

```bash
./run.sh
```

浏览器打开 http://127.0.0.1:8501 。Windows 可执行 `.venv\Scripts\python -m streamlit run src/app.py`。

首次取得真实数据并生成实验：

```bash
.venv/bin/python scripts/download_data.py
.venv/bin/python -m phm.training --prepare
.venv/bin/python scripts/summarize_results.py
```

最后一条命令同步 `validation_status.json`，并生成可离线打开的 `runs/validation_report.html`（图表资源内嵌）。

下载依赖公开服务器。支持重试，已完成文件会复用；失败会明确报错，不会生成假成绩。若机器设置了失效代理，应先修正代理设置。数据与模型仅保存在本地，原始数据不提交版本库。

可单独执行 `--dataset uav` / `--dataset battery` 下载，以及 `--task uav --prepare` / `--task battery --prepare` 训练。界面“模型训练与验证”可从已下载数据重新训练并保存新的实验。

## 页面与演示顺序

侧栏采用主菜单与子菜单导航，当前主菜单展开子菜单，选中项高亮。页面链接包含 `?page=...`，支持刷新后保留当前页面及直接打开子页面。

| 主菜单 | 子菜单 |
|---|---|
| 监测中心 | 装备态势、告警与处置 |
| 装备管理 | 装备档案、新增装备、分系统与部件、数据与模型绑定 |
| 健康分析 | 装备健康分析、故障诊断回放、电池健康与寿命、伺服执行机构诊断、数据导入与推理 |
| 维修管理 | 工单与履历、异常事件与复核、历史窗口复核 |
| 模型中心 | 模型目录与绑定、模型训练与验证、伺服训练与验证、模型版本对比 |

每次仅渲染当前子页面，装备建档、结构维护和绑定操作不再挤在同一页面。离开故障回放页面会暂停播放。

1. **监测中心**：全局装备状态、评估覆盖与异常复核；从告警直接生成维修工单。空数据库可初始化公开数据演示。
2. **装备管理**：建档、维护分系统/部件结构，并绑定具体数据案例、模型版本及观测截止位置。
3. **健康分析**：运行装备分析、查阅历史快照、诊断与 SOH/RUL 趋势；子页面保留故障回放、电池案例及 CSV 导入。
4. **维修管理**：工单从待处理到维修、复检、关闭，保留处理履历；旧事件与窗口复核仍可访问。
5. **模型中心**：模型目录、启停与应用关系；子页面提供训练验证与版本对比。

建议按“装备绑定 → 健康分析 → 监测复核 → 维修闭环 → 模型验证”演示。公开案例和实际装备明确区分；未接入部件显示未评估，整机健康分不虚构。当前本地演示已有无人机、电池台架与无人车结构档案，现场不需要重新下载或训练。

完整功能核对、实现边界与后续大功能见 [五模块实现与功能核对](docs/五模块实现与功能核对.md)。业务状态在 `runs/platform.sqlite`，分析证据在 `runs/analyses/`；请与实验目录一起备份。更新 Python 模块后建议重启 `./run.sh`，避免常驻进程保留旧导入。

## 数据与实验定义

### 无人机：UAV Realistic Fault Dataset

来源：https://github.com/tiiuae/UAV-Realistic-Fault-Dataset

- 首次下载固定当前提交哈希；默认每个类别选择按时间均匀分布的 8 个任务，共 40 个任务。
- 仅使用 SensorCombined 的三轴加速度（m/s²）及角速度（rad/s）；时间戳微秒转秒，按任务归零。音频不下载。
- 任务级标签 0–4 表示损坏螺旋桨数量，不用于具体电机定位。没有飞行中故障起点标签，因此不报告检测延迟。
- 原始信号排序、时间去重、非有限值与加速度裁剪样本剔除，并输出质量报告。2 秒窗口、1 秒步长；不足 100 样本或内部间隔超过 0.2 秒的窗口不推理。
- 每类任务按时间排序，默认 4 个训练 / 2 个验证 / 2 个测试。完整任务隔离；相邻窗口不跨集合。仍不代表跨机体泛化。
- 随机森林五分类；加速度波动阈值作为二分类基线；Isolation Forest 只在健康训练窗口拟合。阈值来自健康验证窗口的 95% 分位数。
- 连续异常窗口合并为误报事件，健康有效窗口数 × 1 秒为曝光时长；短时曝光下每小时率可能很高且不稳定。
- 动力 HI 仅为相对健康训练样本的振动偏离指标，未做工程标定；分类概率不是校准过的置信度。
- 原仓库未发现明确的数据许可声明。保留来源用于本地研究演示；再次分发原始数据或商用前需确认授权。

### 电池：NASA Battery

来源：https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/

下载器从 NASA 官方 ZIP 中按范围提取 `BatteryAgingARC-FY08Q4.zip`，校验 ZIP CRC，读取 B0005/B0006/B0007/B0018 及 README。记录下载来源、压缩包 SHA256 和原始 MAT 哈希。

- 原始 README 明确额定容量 2 Ah，失效判据为容量下降 30% 至 1.4 Ah。本原型取首次观测容量 ≤1.4 Ah 的循环为 EOL。
- SOH = 实测容量 / 2 Ah，这是观测健康量，不是模型预测成绩。
- 容量读取后以放电记录从 1 开始计数；RUL 单位为放电循环，不是小时。
- 未观察到阈值穿越的电池作为右删失样本，保留曲线、不给真实 RUL 标签。只对 EOL 前且有至少 10 个历史循环的样本评分。
- 留一电池验证，输入仅含当前循环、SOH、最近至多 20 循环的容量均值与斜率；未来容量只用于生成评估真值。
- 对比线性阈值外推和随机森林。线性斜率非负时不输出寿命，对比表限定在共同有效样本上。
- 区间半径来自训练电池内部再次留一的绝对误差 90% 分位数，测试电池不参与。独立电池数量很少，属于探索性区间，不声称具有校准覆盖保证。
- 报告 MAE、RMSE、逐电池误差、等权电池 MAE、早中晚阶段误差、实测区间覆盖率和宽度。

引用：B. Saha and K. Goebel (2007), “Battery Data Set”, NASA Ames Research Center.

## 代码与产物

```text
src/app.py                 Streamlit 界面

phm/events.py              SQLite 事件复核记录
scripts/download_data.py   可重试的数据下载与来源清单

validation/                原 RflyMAD 通用适配及独立验证命令
runs/<task>_<id>/           配置、来源、划分、模型、预测、指标与状态
data/raw/                  本地原始数据（不提交）
data/processed/            可重建特征及曲线（不提交）
tests/                     数据泄漏、质量、单位与界面回归测试
```

每次训练新建独立实验目录；异常记录为 failed，不会在界面冒充完成实验。模型 joblib 仅加载本程序生成的可信文件。`runs/events.sqlite` 保存事件处理意见；人工意见不会自动变成训练真值。

RflyMAD 的原映射模板仍需依据实际字段和任务目录配置；当前交互原型默认使用已取得的 TII 数据，未声称完成 RflyMAD 实验。ROS 2/CAN/MAVLink 在线接入、伺服专项模型、UGV 实车验证、经过工程校准的整机风险与完整 MLOps 留待下一阶段。

## 第二轮：CSV 接入、完整异常事件、版本对比

以下能力已归入健康分析、维修管理和模型中心的子页面：

- **数据导入与推理**：UTF-8 CSV 上传、来源字段映射、设备/任务标识检查、秒/毫秒/微秒、g/m/s²、deg/s/rad/s 显式换算；导入前查看重复时间、乱序、缺测、间隔和疑似单位问题。原始 CSV、映射、SHA256、标准化数据和质量报告一并保存至 `data/imports/`。支持不含标签的数据，标签不参与推理。
- **异常事件与复核**：查看首次异常、连续确认、结束原因和上下文曲线；确认、维修、复检、关闭形成有状态约束的事件履历。重复加入事件不会覆盖人工意见，复核不会自动改写训练标签。原窗口级记录继续保留。
- **模型版本对比**：固定原分类模型、数据与任务划分，按健康训练数据建立低/高角运动代理工况；只在验证集选告警参数。对比原始及连续确认后的误报事件数、误报时长、故障窗口召回和任务检出率，并导出独立 HTML/JSON 报告。数据指纹、划分或评估窗口不同会拒绝直接比较。

CSV 当前适配六轴惯性模型，不是所有设备遥测的通用预测器。完整字段是 `device_id,mission_id,timestamp_s,acc_x,acc_y,acc_z,gyro_x,gyro_y,gyro_z`；可选 `operating_mode,label` 用于保留来源信息，当前模型仍使用角运动代理工况。采样至少约 50 Hz，模型窗口 2 秒、步长 1 秒。单文件最多 50 MB / 50 万行、单任务最多一小时，较大数据请按任务拆分。缺少信号可以保存，但输出“无法评估”；不会补零后显示健康。无标签输入不计算准确率或召回率。含标签导入也不自动计入独立验证，避免用户数据与原训练数据重叠。

### 告警实验与选择规则

```bash
.venv/bin/python -m phm.experiments --parent runs/<原无人机基线实验>
```

候选阈值分位数为 0.95/0.975/0.99，连续确认 2/3/5 窗口，解除 2/3 窗口，记录间合并间隔 3 秒。优先降低健康时段告警占比，再比较事件数；约束是验证集故障任务检出率不低于原基线，故障窗口召回率最多下降 5 个百分点。若没有可接受改进，退回原基线，报告不会隐去这一结果。所有候选及资格判断保存在 `validation_candidates.csv`。

代理工况根据健康训练集角速度模长 RMS 的中位数划分；某工况训练/验证健康窗口不足时回退全局基线。它**不等于起飞/降落阶段识别**。当前公开信号没有高度、油门和已确认阶段标签，因此该能力仍待更多信号接入。

告警只在达到连续确认的当前窗口激活，不把此前窗口事后改写为已告警。时间缺口会重置状态，事件不会跨缺口合并。短恢复间隔的事件合并仅影响记录，真实告警时长单独统计，防止“把多个误报合成一次”造成效果假象。首次异常到确认的时间不是故障检测延迟。

### 新增任务评估

```bash
.venv/bin/python scripts/evaluate_fresh.py --run runs/<告警改进实验>
```

先冻结模型与策略哈希并写入选样计划，再按固定规则选择每类两个此前未使用的任务。原任务及已用于其他新增评估的任务会排除。新任务不会进入训练、阈值校准或候选选择。结果保存为 `fresh_evaluation.json`，同时更新该实验的 `comparison.html`。同一版本重复运行会返回封存结果，不重新选样。仍属于同一平台的新任务验证，不代表跨机体泛化；已查看的新任务分数不得用于宣称后续调参的独立成绩。

原分类器保持不变，因此旧测试集分类分数不变是预期行为。本轮目标是降低告警误报并完善数据与维护闭环；NASA 电池模型保持原版，电池扩样、RflyMAD 专用适配和在线协议接入尚待下一轮。

## 伺服执行机构诊断

新增真实公开台架的四状态振动诊断，可查看正常、底座松动、速度调节不佳和电流调节不佳案例；按完整转速工况隔离训练、验证和测试。健康分析新增“伺服执行机构诊断”，模型中心新增“伺服训练与验证”，并支持创建独立伺服台架档案、模型绑定、告警和工单闭环。

```bash
.venv/bin/python scripts/download_servo.py
.venv/bin/python -m phm.servo --prepare
```

使用固定 Mendeley V13、CC BY 4.0 振动数据；首版选择七个共同转速的 56 段完整记录。数据不是同步采集，没有寿命标签，因此不输出指令跟踪残差或伺服 RUL。完整来源、选择范围、处理规则和验证方法见 [伺服诊断数据与验证说明](docs/伺服诊断数据与验证说明.md)。
